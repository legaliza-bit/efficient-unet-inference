# Оптимизация инференса UNet: Сравнение пайплайнов и TVM

## 1. Цели проекта
- Ускорить инференс UNet на датасете Carvana (как аналог ImageNet для сегментации).
- Сравнить end-to-end latency и throughput для нескольких пайплайнов:
  1. PyTorch FP16 baseline
  2. PyTorch `torch.compile`
  3. TVM (Apache TVM) как альтернативный компилятор
  4. Квантизация: INT8/FP8 (через `torchao`)
  5. Спарсификация: pruning / 2:4 sparsity (на текущий момент не интегрирована из-за аппаратных и программных ограничений)

## 2. Имплементация TVM (Пункт 3)
TVM был интегрирован как независимый процесс-воркер, поскольку требует Python 3.11, тогда как остальной пайплайн использует Python 3.13. 
- **Пайплайн компиляции TVM**:
  1. **ONNX Export**: Модель экспортируется из PyTorch в ONNX.
  2. **Relay Import**: `tvm.relay.frontend.from_onnx` загружает граф в высокоуровневое представление.
  3. **Mixed Precision**: Граф переводится в FP16 через `relay.transform.ToMixedPrecision`.
  4. **Optimizations**: Применяются базовые оптимизации: `SimplifyInference`, `FoldConstant`, `FuseOps`.
  5. **AutoTVM Tuning**: Проводится тюнинг через XGBoost-тюнер для выбора лучших расписаний вычислений (convolution, winograd и др.) под конкретную GPU.
  6. **Code Generation**: Граф компилируется в CUDA-ядра (LLVM) с поддержкой вендорных библиотек cuDNN и cuBLAS.

## 3. Методология замера (Benchmarking)
- Использован датасет Carvana.
- Каждая конфигурация проходит прогрев (warmup) 20 итераций.
- Метрики:
  - **Compute Latency**: время `module.run()` на GPU (без H2D/D2H), эквивалентно PyTorch CUDA Events.
  - **End-to-End Latency**: время, включающее аллокацию и копирование данных из RAM в VRAM и обратно.
  - **Quality**: mIoU и Dice, рассчитанные по накопленной Confusion Matrix.

## 4. Результаты

## 5. Выводы по TVM
1. **Качество не страдает**: Модель после конвертации ONNX -> TVM Relay -> FP16 сохраняет метрики (mIoU 0.989, Dice 0.994) без существенных погрешностей.
2. **Производительность**: TVM "из коробки" (без тюнинга) показывает результаты на уровне или немного хуже PyTorch FP16 Baseline. 
3. **AutoTVM**: Применение AutoTVM-тюнинга крайне важно для достижения превосходства над PyTorch. Ввиду сложности графа (UNet) и большого числа слоев, полноценный тюнинг занимает продолжительное время.
4. **Data Transfers**: Накладные расходы на копирование данных (H2D/D2H) вносят небольшую задержку (~3-5 мс), что стоит учитывать при E2E измерениях.
